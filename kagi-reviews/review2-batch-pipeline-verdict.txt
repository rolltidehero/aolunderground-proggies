FINAL SEVERITY-RANKED LIST OF CONFIRMED FINDINGS
F1 - CRITICAL - Stale Decompile Output Saved Under Wrong Filename
Location: batch_decompile.py, decompile_one function
After sending WM_COMMAND to open a new file, the script checks TTreeView item count to determine success. If the new file fails to load, the old file's tree remains populated. The script exports the previous file's decompilation and saves it under the new filename. The checkpoint records success with the wrong file's content. Over 1800 files, this silently corrupts a significant fraction of outputs. No identity verification exists.
Survived pushback: All three models agreed. No challenges.
F2 - CRITICAL - C2 IPC Race Condition Misassociates Commands and Responses
Location: batch_decompile.py and screenshot_proggies.py, c2 function (both copies)
The file-based IPC protocol uses a single shared command file and response file with no request correlation. When a command times out and the next command is issued, the agent may still be processing the old command. The old response is then read as the new command's response, causing wrong window handles, wrong click targets, wrong screenshots, and wrong file saves. This is undetectable at runtime and affects both batch scripts identically.
Survived pushback: All three models agreed. No challenges.
F3 - HIGH - Dialog-Only Screenshot Runs Falsely Marked as Successful
Location: screenshot_proggies.py, screenshot_one function
When no main VB window appears but a dialog was captured, the function returns True with detail "dialog only". The dialog could be a Visual Basic runtime error, a missing DLL message, a registration nag, or a crash report. These false positives poison the checkpoint. The dialog filter excludes only VB Decompiler titles, not generic error patterns.
Survived pushback: All three models agreed. No challenges.
F4 - HIGH - Stale Artifact Contamination on Reruns
Location: single_decompile.py, decompile_exe function
The output directory is created with mkdir(parents=True, exist_ok=True) without clearing it first. pull_decompiled adds new files but never removes files from a previous run. If a re-decompile produces fewer files, old .frm, .bas, and .strings files persist and get incorporated into metadata. The guest directory is also never cleaned.
Survived pushback: All three models agreed. No challenges.
F5 - HIGH - Binary File Corruption via Text-Mode Transfer
Location: single_decompile.py, pull_decompiled function
The QEMU guest-file-open call uses mode "r" instead of "rb". On Windows, text mode translates carriage return plus line feed to line feed and treats byte 0x1A (Ctrl-Z) as end of file. Binary files such as .frx form resources and .res compiled resources are silently corrupted or truncated. Fix is changing one character: "r" to "rb".
Survived pushback: All three models agreed. No challenges.
